Sawarny: booking photographers, with AI built in.

An intelligent mobile application for photographer booking with AI integration. Clients find and book photographers, videographers and studios; both sides sign a contract in the app; and after the event every guest can find the photos they appear in with a selfie.

Context
Graduation project, ISI Mahdia
Timeline
2025–2026
My role
Product design, mobile, API and admin
Platforms
Android and iOS (Expo), web admin

The problem

Hiring a photographer for a wedding, an event or a product shoot is often scattered across social media messages, verbal agreements and photos shared after the event in bulk. Clients struggle to compare creatives, terms are rarely written down, and guests at an event never easily get the photos they're in.

Sawarny puts the whole job in one app: discovery, booking, a signed agreement, live delivery during the event, and personal photo retrieval afterwards.

Who it's for

Accounts are split at sign-up so each type of user gets the right profile and tools.

  • ClientsBrowse portfolios, send booking requests, negotiate the details and sign the contract.
  • Photographers and videographersPublish work, receive and adjust booking requests, run live sessions.
  • Hybrid creatorsProfessionals who offer both photo and video under one profile.
  • StudiosBusinesses that sign up under a studio name instead of a personal one.
  • AdministratorsModerate content, handle reports and support, and configure the AI services from a web dashboard.
  • Event guestsJoin a live session with an access code and retrieve their own photos.

My contribution

I designed the interface in Figma and built the three parts of the product: the React Native mobile app, the Node.js and Express API, and the React admin dashboard. I also integrated the external services (AWS, Cloudinary, Replicate) and set up the Docker Compose deployment.

Architecture

Two clients talk to a single Express API. MongoDB holds the application data; media and AI work is delegated to managed services. Real-time events (session updates, new photos, deletions) travel over Socket.io rooms per user and per session.

Main features

  • Profiles and portfoliosPublications with photos and video, reels, 24-hour stories, followers, ratings and reviews.
  • Discovery and job requestsSearch creatives by type, governorate and minimum rating, browse them on a map, or post a job request with a budget and let creatives respond.
  • Booking and negotiationClients send a request with the event, date, location and amount. The provider can confirm, negotiate new terms or reject; a calendar shows what's coming up.
  • Signed contractsClient and provider each sign on screen. The API renders both signatures, names and signing dates into a PDF contract.
  • Live sessionsThe photographer opens a time-limited session with an access code; guests join, see photos arrive in real time, and the media is deleted automatically after the session.
  • Messaging and supportDirect chat with media, notifications, and a customer-service conversation with the admin team.
  • ModerationReports, warnings and time-limited bans, with bans lifted automatically by a cleanup job.
  • Admin dashboardUsers, bookings, posts, media, reports, support, statistics and the AI configuration in one web app.

AI features

Each AI feature answers a specific need in the product, not a demo for its own sake.

EL Mousawer

LLM assistant via Replicate, streamed

A friendly photography mentor inside the app. It answers questions about cameras, light and editing in a warm, conversational voice, and replies stream word by word so the chat feels immediate.

Sawarny Studio

Image generation via Replicate

Generates and edits images from a text prompt and optional reference photos, directly inside the app.

Find-Me

AWS Rekognition face search

Photos uploaded to a live session are indexed. A guest takes a selfie and gets back only the photos from that session they appear in, after giving explicit consent.

Design decisions

Ask before matching faces. Joining a live session shows a consent screen explaining that photos will be analysed to find the guest. Consent can be withdrawn later from profile settings.

Different sign-up paths for different people. Clients, individual creatives and studios register through separate flows, so a studio is presented by its business name and a photographer by their own.

Small uploads from the phone. Images are resized and compressed on the device before upload, which keeps posting, chat and profile updates quick.

AI settings without redeploying. Admins can change the AI model and API keys from the dashboard. Without a key, the AI features fall back to a mock response, so development never blocks on paid services.

Engineering challenges

  • Giving each guest only their photos

    Challenge: hundreds of event photos, and a guest should only ever see the ones they're in.

    Solution: every uploaded photo is indexed into a Rekognition collection and the resulting face IDs are stored against the photo. A selfie search returns matching face IDs, which are mapped back to photos and filtered to the guest's session. The app only receives short-lived signed S3 links.

  • Not keeping event photos forever

    Challenge: live-session media is personal and shouldn't outlive its purpose.

    Solution: sessions carry a duration and an expiry date. A cleanup service ends expired sessions, then after a configurable number of days deletes the S3 objects, the faces in the Rekognition collection and the database records, and tells connected phones over Socket.io that the session is gone.

  • Contracts both sides can rely on

    Challenge: an agreement made in chat is easy to dispute later.

    Solution: each party draws a signature on screen. Both are stored with the time they were signed and rendered with PDFKit into a contract that includes the booking terms.

  • An assistant that feels responsive

    Challenge: large language models can take several seconds to finish an answer.

    Solution: the API streams the reply as server-sent events and the app renders it as it arrives, through a dedicated streaming hook.
